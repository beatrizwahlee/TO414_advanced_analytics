2. Clean the data

In this next step, we need to prepare the data for the future analysis. This involves both checking for missing values and evaluating if the columns offer the data in a format that makes sense for the prediction.

From the summary and the structure of the data there are already a couple important things to note. Firstly, there are apparently no missing values in the dataset (as we can see that all the statistical values appear to be normal for all variables). Secondly, we can see that most columns are numeric, with exception to age that is in integer form. None of the variables should be converted into factors as they are measured in units and have continuous numerical relationships with concrete strength. Treating them as continuous makes sense because their values can vary in a meaningful way, and the model will benefit from capturing that variation.

3. Split the data

With no need to deal with missing values or column transformations, we are ready to move on to step 3. Splitting data before building a prediction model is essential to evaluate the model’s performance on unseen data. The training set is used to train the model, while the test set is used to assess how well the model generalizes to new data. This ensures that the model isn’t overfitting (performing well only on the training data but poorly on new data) and provides an unbiased evaluation of its predictive performance.

train_rate <- 0.8 #this means that 80% of the dataset will be on the training set
set.seed(0) # this ensures that the same random split to occur each time, which makes model results consistent and comparable across runs 
train_rows <- sample(1:nrow(data), train_rate * nrow(data)) #separate the rows for training

data_train <- data[train_rows, ] # get the set from those rows
data_test <- data[-train_rows, ] # set except those rows

4. Building the model

The idea here is to build the most complete model we can, interaction-heavy model with polynomial terms. After building the complex model, the step function performs backward elimination. This method iteratively removes the least significant variables based on the AIC to reduce the model’s complexity while retaining important predictors. It’s a common method to avoid overfitting while keeping the model’s predictive power.

GiantModel <- lm(strength ~ . + .*.  + I(cement^2) + I(slag^2) + I(ash^2) + I(water^2) + I(superplastic^2) + I(coarseagg^2) + I(fineagg^2) + I(age^2), data = data_train)

5. Prediction

Once the models are built, the trained model is applied to new, unseen data to estimate the target variable. In this case, after training the GiantModel and stepmodel1 models on a set of known data, the prediction step uses the relationships learned during training to predict concrete strength for the test dataset. This step is critical because it assesses how well the model generalizes to new data and provides a measure of its real-world performance. By comparing the predicted values from the models to the actual outcomes in the test set, you can evaluate which model is more accurate and reliable for future use.

giantmodel_prediction <- predict(GiantModel, data_test)

6. Evalute Model

This step is used to evaluate the performance of the GiantModel and stepmodel1 by comparing their predicted concrete strength values to the actual values from the test set. It calculates key metrics like R², which measures how well the model explains the variance in the data, RMSE (Root Mean Squared Error), which indicates the average error in the model’s predictions, and MAE (Mean Absolute Error), which shows the average magnitude of errors. These metrics help determine how accurately each model predicts concrete strength and allows you to compare the two models to identify which performs better for real-world application.

postResample(giantmodel_prediction, data_test$strength)
##      RMSE  Rsquared       MAE 
## 7.6011767 0.8134901 6.0560800
postResample(stepmodel1_prediction, data_test$strength)
##      RMSE  Rsquared       MAE 
## 7.5729491 0.8150656 6.0550198

The evaluation results show that the GiantModel performs slightly worse than the stepmodel1. The stepmodel1 has a lower RMSE (7.57 vs. 7.60) and a marginally higher R² (0.815 vs. 0.813), indicating it explains slightly more variance in concrete strength and has smaller prediction errors. The MAE is also lower for the stepmodel1 (6.055 vs. 6.056), meaning it has slightly more accurate predictions overall. Although the difference is minor, the stepmodel1 provides better predictive performance.
